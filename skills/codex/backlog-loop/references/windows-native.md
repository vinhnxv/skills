# Windows Native Probes.

This text belongs to this skill's `SKILL.md` and is read in full before it runs.

<!-- body -->
- Scope. This file applies only when the platform profile item in `references/preflight-probes.md` resolved `<platform>` to `windows-native`. It replaces the POSIX commands named in the process-hygiene item, the I1 MACHINE GUARD, I8 REAP, and the process scan in `references/run-recovery.md` LIVENESS, and nothing else: every rule those steps state (the reap and re-read cadence, TERM before KILL, never signal what is not proven owned, kill the whole tree) stays in force. The loop never installs, enables, or enters WSL to satisfy a probe, and a missing `sysctl`, `uptime`, `lsof`, `ps -Ao`, or `setpgrp` is not an absent capability on this profile.
- `<cores>`: `$env:NUMBER_OF_PROCESSORS`.
- MACHINE GUARD reading: Windows has no load average. Read, from PowerShell, six samples five seconds apart of `(Get-CimInstance Win32_PerfFormattedData_PerfOS_Processor -Filter "Name='_Total'").PercentProcessorTime` and of `(Get-CimInstance Win32_PerfFormattedData_PerfOS_System).ProcessorQueueLength` (both are locale-independent). The guard is red when the mean CPU is above 90 or the mean queue length is above `2 x <cores>`. A red reading follows the same reap, 2-minute re-read, five re-read, and STOP sequence as the POSIX guard.
- Launch and deadline. A gate, test, build, or app command starts through `Start-Process -PassThru -NoNewWindow` (or `powershell.exe -NoProfile -Command`) and its leader is recorded in `<owned-pgids>` as `<pid>:<creation-time>`, the creation time read from `(Get-CimInstance Win32_Process -Filter "ProcessId=<pid>").CreationDate`. Enforce `<gate-timeout>` with `Wait-Process -Id <pid> -Timeout <seconds>`; on expiry run the tree kill below and record the wrapper status as 124 so the DEADLINE rule reads it unchanged. Keep `CI=1` and the other non-interactive settings as the process-hygiene item states. Stamp the literal text `BACKLOG_LOOP_RUN=<run-id>` into the command line of every command and shell the loop launches (for a PowerShell command, a trailing `# BACKLOG_LOOP_RUN=<run-id>` inside the `-Command` string), and add `BACKLOG_LOOP_ROLE=refresher` the same way to the HEARTBEAT REFRESHER. Still export `BACKLOG_LOOP_RUN=<run-id>` into the session environment for children, but it is not an ownership proof here. While a launcher runs, poll `Wait-Process -Timeout 1` instead of waiting once, and on every poll record each new descendant of the leader (found through `ParentProcessId`) in `<owned-pgids>` as its own `<pid>:<creation-time>`, so a worker that outlives its launcher is already on the list.
- Ownership proof. Windows `ps` and CIM cannot read another process's environment, so the `BACKLOG_LOOP_RUN` token proves nothing on this profile. A process is provably run-owned only when one of these holds: (a) it matches a recorded `<pid>:<creation-time>` itself, or walking `ParentProcessId` upward reaches one, whose current creation time still matches (a mismatch means the PID was reused, so it proves nothing), with every step's parent created before its child; (b) its `ExecutablePath` or `CommandLine` names a path under `<worktree-root>`, which no other worktree or operator path lies inside; or (c) its `CommandLine` contains `BACKLOG_LOOP_RUN=<run-id>` for this run's id. None -> report it, never signal it. Windows does not reparent orphans, and `<owned-pgids>` is in-memory, so the descendant records of the Launch bullet cover a worker orphaned during this run, while (b) and (c) are what a later iteration or a later invocation can still prove.
- Recovery LIVENESS. The scan for a live process carrying an earlier run's `BACKLOG_LOOP_RUN` token reads `CommandLine` and `ExecutablePath` through `Get-CimInstance Win32_Process` for every process on the machine: a `CommandLine` containing `BACKLOG_LOOP_RUN=<that-run-id>` is that token, `BACKLOG_LOOP_ROLE=refresher` in the same `CommandLine` marks a refresher, and a path under `<worktree-root>` belongs to this repository's loop. The repository test, the refresher rule, and the STOP-and-report outcome are exactly the POSIX ones. A worker started with a relative path and no stamp cannot be seen by this scan; the heartbeat age remains the backstop for it.
- Tree kill, replacing the POSIX group kill. For each proven-owned leader or process: `taskkill /PID <pid> /T`, wait 5s, then `taskkill /PID <pid> /T /F` if it survives. Kill the tree, never the leader alone. The dead-run sweep of processes carrying the token becomes the same (a)/(b) proof over `Get-CimInstance Win32_Process`.
- Ports. List listeners with `Get-NetTCPConnection -State Listen -LocalPort <port> -ErrorAction SilentlyContinue | Select-Object -ExpandProperty OwningProcess`, then prove and kill each listener exactly like a leader above. The dev-server log is `$env:TEMP\dev-server-<port>.log`.
- Compose. Unchanged: run the CLEAN-TREE teardown through `docker --context <docker-context> compose ls --all --quiet` only when a `backlog_loop_compose_projects` record exists. No record and no `docker` is not a blocker.
