# Windows Native Probes.

This text belongs to this skill's `SKILL.md` and is read in full before it runs.

<!-- body -->
- Scope. This file applies only when the platform profile item in `references/preflight-probes.md` resolved `<platform>` to `windows-native`. It replaces the POSIX commands named in the process-hygiene item, the I1 MACHINE GUARD, and I8 REAP, and nothing else: every rule those steps state (the reap and re-read cadence, TERM before KILL, never signal what is not proven owned, kill the whole tree) stays in force. The loop never installs, enables, or enters WSL to satisfy a probe, and a missing `sysctl`, `uptime`, `lsof`, `ps -Ao`, or `setpgrp` is not an absent capability on this profile.
- `<cores>`: `$env:NUMBER_OF_PROCESSORS`.
- MACHINE GUARD reading: Windows has no load average. Read, from PowerShell, six samples five seconds apart of `(Get-CimInstance Win32_PerfFormattedData_PerfOS_Processor -Filter "Name='_Total'").PercentProcessorTime` and of `(Get-CimInstance Win32_PerfFormattedData_PerfOS_System).ProcessorQueueLength` (both are locale-independent). The guard is red when the mean CPU is above 90 or the mean queue length is above `2 x <cores>`. A red reading follows the same reap, 2-minute re-read, five re-read, and STOP sequence as the POSIX guard.
- Launch and deadline. A gate, test, build, or app command starts through `Start-Process -PassThru -NoNewWindow` (or `powershell.exe -NoProfile -Command`) and its leader is recorded in `<owned-pgids>` as `<pid>:<creation-time>`, the creation time read from `(Get-CimInstance Win32_Process -Filter "ProcessId=<pid>").CreationDate`. Enforce `<gate-timeout>` with `Wait-Process -Id <pid> -Timeout <seconds>`; on expiry run the tree kill below and record the wrapper status as 124 so the DEADLINE rule reads it unchanged. Keep `CI=1` and the other non-interactive settings as the process-hygiene item states. Still export `BACKLOG_LOOP_RUN=<run-id>`: children inherit it, but it is not the ownership proof here.
- Ownership proof. Windows `ps` and CIM cannot read another process's environment, so the `BACKLOG_LOOP_RUN` token proves nothing on this profile. A process is provably run-owned only when one of these holds: (a) walking `ParentProcessId` upward reaches a recorded `<pid>:<creation-time>` whose current creation time still matches (a mismatch means the PID was reused, so it proves nothing), with every step's parent created before its child; or (b) its `ExecutablePath` or `CommandLine` names a path under `<worktree-root>`, which no other worktree or operator path lies inside. Neither -> report it, never signal it. Windows does not reparent orphans, so (b) is what catches a child whose launcher already exited.
- Tree kill, replacing the POSIX group kill. For each proven-owned leader or process: `taskkill /PID <pid> /T`, wait 5s, then `taskkill /PID <pid> /T /F` if it survives. Kill the tree, never the leader alone. The dead-run sweep of processes carrying the token becomes the same (a)/(b) proof over `Get-CimInstance Win32_Process`.
- Ports. List listeners with `Get-NetTCPConnection -State Listen -LocalPort <port> -ErrorAction SilentlyContinue | Select-Object -ExpandProperty OwningProcess`, then prove and kill each listener exactly like a leader above. The dev-server log is `$env:TEMP\dev-server-<port>.log`.
- Compose. Unchanged: run the CLEAN-TREE teardown through `docker --context <docker-context> compose ls --all --quiet` only when a `backlog_loop_compose_projects` record exists. No record and no `docker` is not a blocker.
