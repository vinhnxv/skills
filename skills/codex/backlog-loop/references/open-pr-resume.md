# Open Pr Resume.

This text belongs to this skill's `SKILL.md` and is read in full before it runs.

<!-- body -->
   OPEN PR RESUME. For each linked PR -- every non-closed issue that carries `backlog_loop_pr` and is not `hooked`, `pinned`, or `deferred`, whatever its cause, found with `bd list --all --limit 0 --has-metadata-key backlog_loop_pr --json`, discarding `closed` rows before any `bd show`, and then `bd show <id> --json` for status and metadata -- query its state, `isDraft`, head, `baseRefName`, base SHA, `mergeStateStatus`, `reviewDecision`, required and optional checks, and any armed auto-merge, then apply LINKED PR DISPOSITION. Every `ce-babysit-pr`, `ce-resolve-pr-feedback`, and `ce-debug` round on a resumed PR runs with the PR branch checked out in a run-owned worktree and never in the invoking tree: those skills push the currently checked-out branch and stop on a dirty checkout. Create it once per PR with `git fetch <remote> <branch>` and `git worktree add <worktree-root>/pr-<number> <branch>`, record `<worktree-root>` in `backlog_loop_worktrees` on every member as CLEAN-TREE GATE RUN does, use it as the working directory for those rounds, and let REAP remove it. A branch that `git worktree list --porcelain` shows checked out elsewhere cannot be added a second time, so add the tree detached instead: `git worktree add --detach <worktree-root>/pr-<number> <remote>/<branch>`. A detached tree has no upstream, so tell the child to push with `git push <remote> HEAD:refs/heads/<branch>` and never with a bare `git push`. When that push cannot happen, a fork PR or a refused push, the issue goes to `needs-person` naming the holder and the refusal. A `needs-person` issue is observe-only: report its row and write nothing, except on `MERGED`, which resumes I7 like any other. An issue at the attempt ceiling stays `needs-person` whatever its PR shows, except on `MERGED`. When the row is adoption, adopt every member through ADOPTION first, so no other invocation can take the PR while its gates run, then run the complete applicable local quality gate set on the exact current head in CLEAN-TREE GATE RUN unless `backlog_loop_gate_receipt` already holds this head, this base, and the current gate-set digest; a green run rewrites the receipt. Once every gate passes, write `backlog_loop_phase=merge-requested` on each member and perform I6's guarded merge against that same head; a changed head or base requires new exact-commit gates and never reuses an old receipt. On merge, continue I7 for those same members. Never create a second PR, and never reset the attempt count, during this pass.
