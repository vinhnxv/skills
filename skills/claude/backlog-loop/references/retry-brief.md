   RETRY BRIEF. A member recorded `transient:review-residual` is a retry too: its brief lists every residual from the notes and the branch and head named in the `last branch ..., head ...` note RELEASE GUARD wrote (the reopen cleared the live keys), starting from that branch when it still exists, and the child fixes each one itself, with a regression test where the finding concerns behavior. It never dismisses, ticks, or reclassifies a finding, because only the review decides that. P4 then reviews the result again; a review with no actionable residual crosses the gate, and a residual that persists or recurs is written `needs-person` with the finding named, and a residual that needs a design decision is written `transient:decision-recorded` through I7, unless it is a `settled_conflict`, changes a contract, permission, or security stance, or contradicts a `user-approved` decision, which is written `needs-person` with the question named. A member recorded `transient:decision-recorded` is a retry too: its brief maps the newest decision entry in its design field into LFG's settled-decisions brief exactly as for an owner-decision member, so the new planning request cannot reopen the question. A member recorded `transient:scope-incomplete` is a retry too, but not a debugging one: no work failed. Its brief starts from the branch and head named in the `last branch ..., head ...` note (when the branch still exists), states the complete atomic `<trunk-failures>` set including the omitted failures its note names, and requires the exact failed checks of the whole set and the complete gate set to pass before shipping. It does not repeat the focused proof's work. A member whose `backlog_loop_attempts` is at least 1 and whose notes hold a `pipeline blocked: gate failed:` entry is a retry. Its brief states the failing command and exact error from those notes and every earlier `retry-hypothesis`. Before any edit, the child reproduces the failure with that command, runs `compound-engineering:ce-debug` (or `investigate-first` when ce-debug is unavailable) to rank causes by evidence, and appends `retry-hypothesis: <cause> | <evidence> | <planned change>` to the notes. The hypothesis must differ in cause or layer from every earlier one; a repeat is not an attempt, so the member is written `needs-person` with the repeat named. The child never weakens, skips, or deletes the failing assertion to pass the gate. A failure that does not reproduce in 3 consecutive clean runs of the exact command is recorded as `intermittent` with the pass count; it still counts as an attempt and keeps the gate red until the full gate set passes.
